# 删除一律先进废纸篓

一句话规则：**任何让文件内容消失的操作，默认都走废纸篓；只有用户明确说要永久删除，才用真删除。**

判断锚点：动手前问自己「这条命令跑完，某个文件的内容还能不能拿回来？」答案是不能 → 换成移入废纸篓。

## 默认动作：移入废纸篓

覆盖这些入口，它们本质都是删除：`rm` / `rmdir` / `unlink` / `find ... -delete` / `git clean` / `rsync --delete` / `tar --remove-files` / `npm cache clean` 之类工具自带清理，以及覆盖写（`>` 重定向、`truncate`、`cp` 覆盖、`mv` 覆盖）。

首选（本机已实测可用，支持文件、目录、多参数）：

```bash
/usr/bin/trash -v /abs/path/to/target
```

- 一律用绝对路径；`-v` 会打印它实际落到 `~/.Trash` 的位置，把这段输出转述给用户。
- 多个目标一次传给 `trash`，或逐个调用都行；不要在同一批里混用 `rm` 和 `trash`。
- 目录整体 trash，不要「先删内容再删空目录」——那会让目录结构不可恢复。
- 校验只看「源路径已不存在」。**不要用 `ls ~/.Trash` 校验**：本机 shell 读那个目录会被系统拒绝（`Operation not permitted`），这不是失败。
- 要删的文件很多（几十上百个、或几 GB）也照样 trash，不要因为「量大」退回 `rm`。

备选实现（首选不可用时按序退化，`scripts/trash.sh` 已封装好这三层）：

```bash
osascript -e 'tell application "Finder" to delete POSIX file "/abs/path"'
mv /abs/path "$HOME/.Trash/$(basename /abs/path).$(date +%Y%m%d%H%M%S)"   # 会丢「放回原处」
```

`mv` 到废纸篓目录是最后兜底：重名必须加时间戳（否则静默覆盖废纸篓里的同名旧文件），而且要告诉用户这项没法用 Finder 的「放回原处」。

## 什么时候可以用真删除

- 用户明确表达了永久删除的意思，并且范围具体到路径：「永久删除」「直接删掉，不用进废纸篓」「彻底清除」「别留备份」——这时才对**他点名的那些路径**用 `rm`。
- 「清理一下」「整理下目录」「这些不要了」「删掉不需要的」**都不算确认**，照旧进废纸篓。废纸篓就是给自己留后路的地方，多这一步几乎没有成本。
- 一次确认只管当次、只管它点名的范围。不要顺延到下一次操作，也不要顺手扩大到相邻文件或整个目录。
- 不要替用户清空废纸篓（`rm -rf ~/.Trash/*`、Finder 的「清倒废纸篓」都留给用户自己）；要腾空间时提醒他自己清。

## 同源的破坏性操作同样按此处理

- **覆盖 / 截断已有文件**：先把原件移入废纸篓（或另存一份），再写新内容。直接 `>` 覆盖等于把旧版本永久抹掉，用户往往不知道它有过内容。
- **git 丢弃改动**：`git clean -fd`、`git reset --hard`、`git checkout -- .`、`git restore` 会永久丢掉未提交和未跟踪的工作。改动的价值常常是不可再生的代码，所以先 `git stash -u`（或提交到临时分支）留个后路，再执行；不要拿 `git clean` 当「清理」的默认手段。
- **数据库 / 不可回收的删除**：`DROP`、`DELETE`、`--prune` 这类没有废纸篓可放。先导出备份（`cp` 数据库文件或导出 dump）并拿到用户确认，再执行。

## 唯一例外

- 本次会话里自己刚创建的探测/临时文件，且位于系统临时目录（`$TMPDIR`、`/tmp`、`/var/folders/...`）内，可以直接删——纯粹为了不让废纸篓堆满测试残留。两条同时满足才行：本会话新建 + 在临时目录里。（不想要这个例外，删掉本节即可。）
- 反过来的情况要交回用户：清理 `node_modules`、`dist`、`.cache`、`__pycache__` 这类体积大但可再生的目录时，虽然理论上可再生，也不要自己决定直删——问一句「直接删还是先进废纸篓」，把判断权还给用户。

## 收尾话术

做完之后，明确区分三种结果，不要混为一谈：

- 移入废纸篓 → 说「已移入废纸篓」，给出路径，并说明恢复方式：Finder 废纸篓里右键「放回原处」，或 `mv ~/.Trash/<名字> <原路径>`。
- 永久删除（已获用户确认）→ 说「已永久删除」并列出路径，让用户知道这次回不来了。
- 只是跳过、没删（路径不存在、被权限拦住）→ 直说没删成、原因是什么，不要含糊地说「已清理」。

正例：用户说「把 build 目录清掉」→ `trash -v /abs/build`，回「已移入废纸篓，可在废纸篓里放回原处」。
反例：用户说「把 build 目录清掉」→ 直接 `rm -rf build`，然后只回一句「done」——双方都不知道旧产物还能不能找回来。

## 脚本

`scripts/trash.sh <路径...>`：优先 `/usr/bin/trash` → `gio trash`（Linux）→ Finder（保留「放回原处」）→ `mv` 兜底，逐个打印落点，跳过不存在的路径并以非零码退出（方便调用方发现没删成）。写删除逻辑时用它，别手写 `rm` 分支。
