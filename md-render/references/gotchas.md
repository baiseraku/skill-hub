# 翻车记录：每条规则是怎么来的

这些都是在这份中文科研报告（约 750 行 md、33 张图、16 张表）上真实踩过的，
按出现频率排序。规则不是审美偏好，是避免这些具体故障。

## 1. 中文里的 markdown 加粗会静默失效，`**` 直接印出来

CommonMark 的定界符规则要求**开定界符不能被「非空白非标点」的字符紧邻后跟标点**，
而中文写法经常同时踩两条：

```markdown
一律是**"签名高的 spot"**，不是…      ← 开 ** 前是汉字（非标点）、后是引号（标点）→ 不成对
四条轴用**同一套预设变体（供体）**比较  ← 闭 ** 前是「）」标点、后是汉字 → 不成对
```

结果：`**` 原样留在正文里，读者看到星号。`md_to_html.cjs` 的做法是先让 marked 解析一遍，
**只在结果里还有字面 `**` 时**，把源码里成对的 `**…**` 换成 `<strong>` 再解析一次。
不要一上来就全局替换——那会干扰正常段落里的嵌套标记。

## 2. 表格把数值/文件名从中间劈开

三种诱因，别只修一种：

1. `th,td { overflow-wrap: anywhere }` —— 这会让单元格的最小内容宽度塌成 1 个字符，
   浏览器在自动布局时不再为整词保留空间，于是 `0.0178` 变成 `0.017` + `8`。
   **要用 `break-word`**（只在整词放不下时才断），并且 `word-break: normal`。
2. 表格自动布局按各列「最长一行」的比例分宽度，**中文列的最长一行极宽**，
   会把含长路径的窄列挤到低于其最小内容宽度。解法是量出每列最小/最大内容宽度后
   `table-layout: fixed` + `<colgroup>` 写死列宽（`measure_columns.cjs` + `colWidthsFor`）。
3. 即使写了断点，断点位置也不理想：`GSE241664_read_counts.csv.gz` 在 `/` 和 `_` 处断开可以接受，
   在 `read_` 与 `counts` 之间被劈开就难看。所以在 `_` `/` 后插 `<wbr>`（只提供断行机会、
   不产生字符，复制路径不受影响），而不是插入零宽空格（会把不可见字符带进复制的文本里）。

数字要额外保护：`2.44（P = 3.0e-04）` 这种，浏览器会贪心地把 `2.44（P = 3.0e-` 塞满一行，
把 `04）` 甩到下一行。给数值 token 包 `white-space: nowrap` 才能让它整体换行。

## 3. 列宽分配：先满足最小宽度，再分余量

按「最长内容的比例」分配必然失败（中文列最长内容动辄几千 px，见 `measure_columns.cjs` 的输出：
最长 1669pt vs 最小 421pt）。正确顺序是：

1. 每列先给它的**最小内容宽度**（不这样就会拆词）；
2. 剩余空间按「想多要多少」分，但**单列最多再拿栏宽的 35%**，防止长文本列独吞；
3. 若连最小宽度之和都超栏宽，**整表缩字号**（下限 ≈7pt）而不是让浏览器去拆词。

## 4. 测量时视口必须等于打印正文栏宽

第一次测量时用了默认视口（1280px），量出来的「正文栏宽 960pt」，而实际打印是 499pt——
列宽全部算错，问题看起来像"规则没生效"。正确做法：从 `@page { size; margin }` 推算正文栏宽
（A4 宽 210mm − 左右各 17mm = 176mm = 665px @96dpi），用这个宽度建视口再量。
`measure_columns.cjs` 现在会自动推算，也支持 `--content-width` 覆盖。

## 5. `$` 会被当成数学公式

Chromium 打印流水线（如 pdf skill 的 `html2pdf-next.js`）里有一步检测
`/\$[^$]+\$/`，中文报告里 `sc$donor`、`data$` 这类 R 代码标识符会命中，于是它去 CDN
拉 KaTeX——离线环境直接失败中断渲染。`md_to_html.cjs` 在 `<body>` 里放了一个空的
`renderMathInElement`，既满足「库已加载」的检测，又什么都不渲染。

## 6. 两端对齐 + 长 token = 字间空洞

`text-align: justify` 遇上无法断行的长路径，会把整行拉出几字宽的空洞，逗号、顿号浮在空白里。
中文报告里不值得为「右边缘齐」付这个代价，直接左对齐；汉字宽度一致，参差本来就不明显。

## 7. 图整幅落版，不做绕排

`figure { break-inside: avoid }` + 图注紧随其下。副作用是图放不下时会整块推到下一页、
页尾留白——这是可接受的代价，比图被页面切开或图注和正文重叠好得多。
如果要压这种留白，只能整体缩小图（`max-width: 88%` 之类），别去动 `break-inside`。

## 8. 排版细节

- 表格表头每页重复：`thead { display: table-header-group }`。
- 行不要被跨页切断：`tr { break-inside: avoid }`。
- 标题不要孤立在页底：`h2,h3,h4 { break-after: avoid }`。
- 目录用 flex + 点线（`.dots` 的 `border-bottom: dotted`），页码用 `tabular-nums`，
  不要用 `……` 字符堆引导点（换行时对不齐）。
- 文首副标题：h1 之后若紧跟一个 ≤60 字的短段落就当副标题居中显示（`md_to_html.cjs` 的启发式）；
  不是这个结构就加不了，别硬猜。

## 9. 交付形态

科研/技术报告常要"发给别人看"，而 md 里的图是分散的 PNG。两个产物一起给：
相对路径版（便于继续改）和 `--inline-images` 的单文件版（4–5 MB，直接传）。
自检脚本里 `--expect-figures/--expect-tables` 用 md 里的实际数量，别凭印象填。

## 10. 转 PDF 时的两个硬约束

- **页码不能在 HTML 里写。** Chromium 不支持 `@page { @bottom-center { content: counter(page) } }`
  这类 CSS 页边内容（不报错，只是不生效）。页码只能渲染完用 pdf-lib 画上去
  （`html_to_pdf.cjs` 的页脚部分，默认前 1 页不编号）。
- **目录页码必须两轮。** 页码要在渲染前写进 HTML，而真实页码只有渲染后才知道：
  先出一版占位页码（`--placeholder 00`，占位宽度要与真实页码一致，否则会重排）→ 渲染 PDF 并导出映射
  （`--map-out`）→ 用 `--pages` 重出 HTML → 再渲染 PDF，并用 `--verify-map` 复核分页没被改掉。
  纯在线阅读的 HTML 不要显示页码，省掉这两轮。

**提取标题页码时先做 NFKC 归一化。** Chromium 导出的 PDF 里，一部分汉字（一、生、文、片、自、
用、小、无、行、面、支…）的 ToUnicode 映射落在康熙部首区（U+2F00–U+2FDF），直接拿标题字符串
去匹配会有一半找不到；NFKC 会把「⽂」折回「文」。`html_to_pdf.cjs` 里的 `norm()` 做的就是这件事。

**顺手记两个坑**：① 用 `html2pdf-next.js`（pdf skill 那套）时它会检测 `$…$` 判数学公式并去 CDN
拉 KaTeX——离线必然失败中断，HTML 里放个空 `renderMathInElement` 即可（`md_to_html.cjs` 已内置）；
② 别把 `chrome-headless-shell` 的位置做成指向完整 Chrome 的符号链接，macOS 上会崩溃弹窗。
