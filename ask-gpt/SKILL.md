# 问 GPT

**整理措辞 → 交给 Codex CLI → 原样返回答案。** 三条硬约束：

1. **改写的是措辞，不是问题。** 不许改动用户问题的本意。
2. **返回的是 GPT 的原始回答。** 不附加你的修正、评价或补充。
3. **答案下面只附模型和思考强度**，一行；证据路径、会话 id、哈希都不进回答。

## 整理：只许做两件事

1. **去掉口语废话**（"那个"、"就是说"、"你帮我看看"）。
2. **把指代补成明确对象**（"这俩"、"我那个脚本" → 具体所指）。这是让 GPT 听得懂，不是改问题。

**除此之外一个字都别动**：不新增比较维度、不新增约束、不新增子问题、不换问法。用户原话里自己提了答案形状（"列个表"、"一句话"）就带上，没提就别替他规定。跟着用户的语言走，中文问就中文发。

反例：用户问「Rust 和 Go 哪个更适合写 CLI？」
✗ 发成「请从编译产物大小、启动延迟、生态成熟度三方面比较……」——那三个维度是**你想的**。
✓ 发成「Rust 和 Go 哪个更适合写命令行工具？」——只去口语成分，问题原封不动。

密钥、凭证、内部人名、私有路径不要写进去：整段问题会发到第三方 relay。非带不可就停下来问用户。

## 思考强度：由你定，用户指定优先

**每次都要给 `ASK_GPT_EFFORT`，脚本会强制**——不给直接报错，不会退回配置文件的值（那样就不叫"你定"）。用户说了档位就照用户说的；确实想用配置值要显式写 `ASK_GPT_EFFORT=config`。

| 问题的样子 | 用 |
| --- | --- |
| 事实确认、解释、翻译、格式整理、只要一句话 | `low` |
| 常规分析、方案对比、写法建议、开放式意见——**拿不准就用这个** | `medium` |
| 多步推理、代码/数学/架构权衡、易被表面答案骗过 | `high` |
| 明确困难、没有标准答案、需要反复权衡 | `xhigh` / `max` |

六个档位实测都可用；另有 `ultra`，它与 `max` 的差别没验证过，没有明确理由别用。别为了稳一律 `high`——那等于没做判断。**别声称"档位越高越贵"**：实测单次 token 数波动很大，拿它当依据会出错。用户嫌浅就提高一档重问，并说明那是**重问出的新答案**，不是在修正旧答案。

## 调用

```bash
ASK_GPT_EFFORT=medium ~/.agents/skills/ask-gpt/scripts/ask_gpt.sh <<'GPT_PROMPT_EOF'
<整理后的问题>
GPT_PROMPT_EOF
```

- 问题**只走 stdin**（heredoc）。脚本不收任何命令行参数，传了会报错提示你。
- 默认**不留任何文件**（不写 rollout，临时文件跑完即清）；`ASK_GPT_KEEP=1` 留可核验的证据（落在 `~/Library/Caches/ask-gpt/`，清理软件会回收，不永久占存储；`ASK_GPT_HOME` 改位置），`ASK_GPT_MODEL` 换模型。
- 要读用户项目里的文件：`ASK_GPT_CWD=<项目目录>`，并在问题里点名文件。
- Bash 超时给 300000ms——一次 codex 回合十几秒到一分钟都正常。

脚本会在 stderr 打出本次的**模型与思考强度**（codex banner 里的生效值，被覆盖后会跟着变），照抄它写进回答。

## 回报

> **问了 GPT**：Rust 和 Go 哪个更适合写命令行工具？
>
> **GPT 的回答**：
> （原文照抄，一字不改）
>
> `gpt-5.6-sol` ｜ 思考强度 `medium`

- 把**实际发出去的问题**亮出来，用户才能核对你没动原意。
- 答案原样贴。"不过要注意"、"这条我没核实"这类都算加了修正，用户明确不要。
- 失败就把 stderr 里 Codex 的报错原文贴出来（`ERROR: unexpected status 503 ...` 是 relay 自己的话），**绝不要自己编一个答案填上**。
- 唯一的例外：答案让用户执行破坏性操作（删数据、覆盖文件）时，该确认还是要确认。

## 用户问「我怎么知道这不是你编的」

别辩解，把能查的指出来：

1. **relay 服务端日志（最硬）**：`deepcoding.sbs` 记了每次请求的模型、时间、token、request id。让他去面板查这次调用——我编答案就不会有这条记录，这是我伪造不了的。
2. **本机凭据（弱，默认没有）**：默认不留文件，这条路径是空的，别暗示有东西可查。用 `ASK_GPT_KEEP=1` 重跑才有 `~/Library/Caches/ask-gpt/calls/<时间戳>/`（问题、回答、banner）和 codex 自己写的 rollout。要清理就直接删它，或交给清理软件。
3. **自己跑一遍（完全不含我）**：给他带上 `ASK_GPT_EFFORT` 的完整命令，并提前说明不给强度会报错。

三条边界不要绕：本机文件我都能写、能伪造；请求真发出去也只证明"发到了那个 relay 并取回了文字"，不证明背后是 GPT；要彻底排除我只有第 3 条。

## 排查

- `No available channel for model ...`：relay 上没有该模型名的渠道；模型名**区分大小写**（`gpt-5.6-sol` 可用，`GPT-5.6-sol` 会 503）。
- `Model metadata not found`：只是 codex 不认识这个模型 id，不影响使用。
- 找不到 CLI：默认找 `/Applications/ChatGPT.app/Contents/Resources/codex`，可用 `ASK_GPT_CODEX` 覆盖。
- 一次调用几千 token，用户问得很密可以提一句。
