# Agent 交接文档（HANDOFF.html）

把一个项目的当前状态写成任何接手 agent 都能**零上下文继续工作**的 HTML 交接文档，固定落盘到项目根目录 `HANDOFF.html`。交接文档是**活文档**：建立后随工作进展持续更新，不是一次性交付物。模板在本 skill 目录下：`assets/HANDOFF-template.html`。

## 核心原则

这些原则决定文档质量，动手前先读：

- **读者是零上下文的接手 agent**，它看不到交接方的聊天记录。自查标准：只读这份文档，能否不追问就继续干活。不写「按之前说的做」，写具体文件、命令、参数。
- **最重要的放最前**：第 1 节是状态快照 + 下一步起点（精确到 `文件:行号` 或第一条命令）。接手 agent 可能只精读这一节就开工，细节按需往后查。
- **只写可核验事实**：内容必须来自对项目的实际查看（README、脚本、日志、输出文件），不许凭聊天记忆或想象填写。查不到就写「未记录」；推测要标「待验证」，结论要标「已验证」——模板配色已区分这三类。
- **每个结论带证据位置**：日志路径、输出文件路径，让接手者能自行复核而不是信任转述。
- **写已尝试的失败路径**：这比已完成事项更省接手者的时间，避免重走死路。
- **写红线（不要做）**：勿重跑的昂贵操作、只读数据、已知坑。护栏对 agent 特别有效。
- **下一步四要素**：动作 + 起点 + 预期产出 + 完成判定，缺一项就不算合格的待办。
- **不写敏感信息**：密钥、token、内网地址用环境变量名或「见某存储位置」指代。

## 操作流程

### 新建（项目还没有 HANDOFF.html）

1. 读模板 `assets/HANDOFF-template.html`，复制到目标项目根目录命名为 `HANDOFF.html`。
2. **先调查再填写**：读项目 README 与现有文档、列关键文件、核对第 4 节要写的命令真实存在且可执行、核对第 5 节要写的产物文件确实在。禁止跳过调查直接凭对话记忆填。
3. 用实际内容替换全部 `{占位符}`；没有对应内容的节（如无阻塞）整节删除，不留空壳。
4. 删除所有 `class="tpl"` 的红色填写说明段落（含顶部使用说明）。模板的 CSS 骨架、配色标签和分节结构保留，不增删节。
5. 项目有 README.md 时，在其中加入指向 `HANDOFF.html` 的链接；没有 README 时不必为此新建。

### 更新（项目已有 HANDOFF.html）

1. 先通读现有 HANDOFF.html，**在其上修改，不推倒重建**——分节结构和已确认事实是资产。
2. 同步更新头部 `<time>` 的 `datetime` 属性与可见日期、「交接方向」「当前阶段」「下一步起点」「文档状态」。
3. 新完成的事项移入第 5 节并补证据位置，同时从第 6/9 节移除；新发现的失败尝试与阻塞写入第 6 节；下一步清单按当前实际重排。
4. 接手约定变化（如新增红线、依赖变更）时，同步第 4/8 节。

## 持续更新约定（文档建立后即生效）

HANDOFF.html 一经建立（或接手维护），以下时点必须**主动**更新，不等用户提醒。首次建立时向用户说明本约定已生效：

- **完成任一行动或阶段收尾时**：事项移入第 5 节并补证据位置，同步第 1 节快照与「下一步起点」。
- **出现新阻塞、失败尝试或红线时**：立即写入第 6/8 节——这是对后来者价值最高的信息，拖延就会丢。
- **做出关键决策、运行方式或环境变化时**：同步第 4/7 节。
- **会话收尾或准备交接前**：核对文档与项目实际状态一致（命令可跑、产物在、下一步起点正确），更新头部 `<time>` 与「文档状态」。

更新纪律：

- 就地修改受影响的小节，不推倒重建；每次更新同步改 `<time>` 的 `datetime` 属性与可见日期。
- 以「事实变化」为更新粒度，不必每条命令后都写；但任何收尾时刻，文档必须与实际一致。
- 更新必须落盘到 HANDOFF.html 本身，只在聊天里总结不算更新。

## HTML 格式约束

- 保持语义化轻量：只用 h1/h2、table、ul/ol、code、pre，无 JS，CSS 维持模板现有规模不扩写。文档会被接手 agent 整段读进上下文，花哨样式是纯 token 开销。
- 路径、命令一律放 `<code>`，命令序列放 `<pre>`，保证换行不丢。
- 状态用模板的标记类：✅ `st-done` / 🔄 `st-wip` / ⛔ `st-blocked` / ⏭️ `st-todo`；结论可信度用 `confirmed` / `assumed` / `unknown` 配色类。
- 本 skill 固定 HTML 是为人机共读（接手者可能包括用户本人）；纯 agent 链路下 Markdown 更省 token，但除非用户明确要求，不改格式。

## 交付自查

写完通读一遍，逐条核对后再交付：

- 占位符是否清零、`tpl` 段落是否删净、空节是否已删？
- 只凭文档能否开工？「下一步起点」是否精确到文件:行号或命令？
- 每条结论是否带证据位置，或明确标了「未记录 / 待验证」？
- 文中命令与产物路径是否实际核对过存在？
- 是否混入敏感信息？
- 新建场景：是否已向用户说明持续更新约定已生效？
